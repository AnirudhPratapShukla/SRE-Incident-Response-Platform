SRE MULTI-AGENT v1.0 DEMO / RUN GUIDE =================

GitHub: https://github.com/AnirudhPratapShukla/SRE-Multi-Agent

Purpose

This guide is for demonstrating the SRE Multi-Agent project from a fresh
PowerShell session. It contains the commands needed to set up the
project, configure dependencies, start Ollama, prepare the RAG data, run
the CLI/API, approve a remediation, and run the test suite.

IMPORTANT

1.  Never show or share the real .env file or API keys.
2.  Keep GOOGLE_API_KEY and PINECONE_API_KEY private.
3.  The v1.0 remediation layer is planning-only and does not make
    production infrastructure changes.
4.  The expensive Ollama/RAG end-to-end workflow does not need to be run
    for every code change.
5.  This guide assumes the repository is already pushed to GitHub.

12. WHAT TO EXPLAIN DURING THE DEMO
======================================================================

When showing the project to someone, explain the agents in this order.

MONITORING AGENT

Collects service metrics such as CPU, memory, latency and error rate.

LOG AGENT

Analyzes application logs and looks for database failures, connection
timeouts, HTTP 500 errors and other runtime signals.

INFRASTRUCTURE AGENT

Checks simulated infrastructure health such as pod status, replica
counts, restarts and deployment health.

RAG AGENT

Searches historical incidents in Pinecone using semantic similarity.
This gives the RCA Agent previous incidents that are similar to the
current problem.

RCA AGENT

Combines the current incident, metrics, logs, infrastructure information
and historical incidents to produce a structured root-cause analysis.

SAFETY AGENT

Checks whether the recommended remediation is potentially destructive.
Unsafe actions are blocked.

HUMAN APPROVAL

The workflow pauses and waits for an explicit human decision. The AI
does not approve its own remediation.

REMEDIATION AGENT

Creates a controlled remediation plan after approval. In v1.0 it does
not directly modify production infrastructure.

production.

14. SAFETY DEMO

Examples include:

    drop database

The purpose is to demonstrate that the AI system has a safety gate
before human-approved remediation.

17. API DEMO
======================================================================

Create an incident using:

    POST /incident

Example JSON:

    {
      "incident": "The order-api service is returning HTTP 500 errors and requests are timing out",
      "service": "order-api"
    }

The API returns a thread ID and incident/workflow information.

The workflow can then be approved using:

    POST /incident/{thread_id}/approve

Example JSON:

    {
      "approval": "yes"
    }

The approval endpoint resumes the interrupted workflow.

======================================================================
18. API DEMO USING POWERSHELL
======================================================================

If you want to demonstrate without Postman, use:

    $body = @{
        incident = "The order-api service is returning HTTP 500 errors and requests are timing out"
        service  = "order-api"
    } | ConvertTo-Json

Then:

    Invoke-RestMethod `
      -Uri "http://localhost:8000/incident" `
      -Method POST `
      -ContentType "application/json" `
      -Body $body

Save the returned thread_id.

Then approve:

    $approval = @{
        approval = "yes"
    } | ConvertTo-Json

    Invoke-RestMethod `
      -Uri "http://localhost:8000/incident/<THREAD_ID>/approve" `
      -Method POST `
      -ContentType "application/json" `
      -Body $approval
